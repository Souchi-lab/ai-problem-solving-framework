# Agent: Judge

## 役割定義

Judge は「このループを完了してよいか」を最終判断するエージェントである。

- Goal の成功基準と現在の成果物を照合する
- Improve を続けるか、ループを終了するかを決定する
- 完了した場合は `result.md` の作成を指示する

---

## v0.1 における位置づけ

**v0.1 では、Judge は人間が兼任する。**

理由:
- 成功基準の解釈には文脈・価値観が伴い、AI 単独では判断しきれないケースが多い
- v0.1 の目的は「ループを回す仕組みを作ること」であり、自動評価は次の課題
- 人間が Judge を担当することで、フレームワーク自体の問題点も発見しやすい

運用方法:
- `review.md` を読んで、自分で「続けるか／終えるか」を判断する
- 判断基準は `goal.md` の Success Criteria を参照する
- 判断したら `improve.md` または `result.md` を書いてループを進める

---

## 判断フロー（v0.1）

```
review.md を読む
    ↓
Goal の Success Criteria を確認する
    ↓
成功基準を満たしているか？
    ├─ Yes → result.md を書いてループ完了
    └─ No  → improve.md を書いて次 iteration へ
                ↓
            改善の余地があるか？ / リソースは続けられるか？
                ├─ Yes → Plan または Build から再開
                └─ No  → result.md に「中断」として記録して完了
```

---

## 評価観点の草案

Judge が確認すべき観点：

```
1. Goal の成功基準を満たしているか？（必須）
2. Critic が指摘した Critical リスクは解消されているか？
3. 残っている課題は「次の run」で扱えるレベルか？
4. このループから得た学び・一般化できる知見は何か？
5. フレームワーク自体の問題点（改善点）はあったか？
```

---

## 将来的な独立 Agent 化の展望（v0.2+）

v0.2 以降では、Judge を独立した AI Agent として定義することを検討する。

条件:
- 定量的な成功基準が定義されている（テストカバレッジ / 指標値 / etc.）
- 評価プロセスが自動化できるレベルで標準化されている

課題:
- 定性的な成功基準（「使い心地が良い」など）の自動評価は困難
- Judge のミスジャッジがループを早期終了させるリスクがある

暫定方針:
- **定量基準 → AI Judge**、**定性基準 → 人間 Judge** のハイブリッド構成
- Judge の判断ログも記録し、Judge 自体の精度を改善できる仕組みを作る
