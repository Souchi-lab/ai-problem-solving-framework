## Execution Intent

This run is about writing discipline.

It exists to define how already-accepted compare routing evidence should be
turned into prose for `docs/compare` without reopening:

- candidate discovery
- rule refinement
- migration judgment

The writing should explain why certain assets deserve compare treatment,
not use compare prose as a place to continue unresolved design work.

---

## Compare Writing Scope Policy

The compare writing scope is limited to assets already admitted by the routing step.

This means:

- the prose should start from the shortlist
- the prose should explain already-identified structural ambiguity or difference
- the prose should not introduce new compare candidates

Writing scope is therefore:

- translation of routing evidence into explanatory prose
- not expansion of compare evidence

---

## Primary Vs Conditional Subject Policy

### Primary Subjects

The primary compare-writing subjects are:

- `framework/planning-patterns.md`
- `src/apsf/viewer/api.py`

These two should anchor the compare prose because they already qualify as strong compare candidates.

### Conditional Subject

The conditional compare-writing subject is:

- `src/apsf/storage/run_repository.py`

It may appear only as a conditional note or subordinate compare case.
It should not become the main narrative driver unless later evidence clearly raises it above conditional status.

---

## Structural Explanation Policy

Compare prose should explain only the already-established structural basis for compare.

Valid explanation types:

- structural ambiguity
- structural difference
- boundary stress
- extraction-versus-whole-placement tension

The prose should answer:

- why this asset belongs in compare
- what structural issue the reader should see
- why direct placement alone would hide an important distinction

The prose should not answer:

- how to refactor the code
- how to migrate the repo
- what final rule refinement must be adopted

---

## Writing Exclusion Policy

Do not include the following in compare prose.

- new compare candidate discovery
- rule refinement proposals
- migration sequencing
- implementation instructions
- generic asset importance claims
- unresolved unread-state speculation

Also exclude any writing move that turns compare into:

- fallback design storage
- hidden shared layer
- indirect migration planning
