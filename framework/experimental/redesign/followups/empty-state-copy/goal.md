# Goal

---

## Follow-up Context

- Parent series:
  SoChi BLOCKS 初回体験改善
- Previous result:
  トップページと遊び方ページは、
  `説明する`
  より
  `迷わず始められる`
  方向へ整理する流れが見えている
- New trigger:
  `Cleared: 0 / 0`
  のような空状態表示が、
  未開始ではなく
  `壊れて見える`
  印象を与えている
- Scope limit:
  空状態の UI 文言と見せ方の整理のみ
- Non-goals:
  進捗システム redesign / 実績機能追加 / 全 UI 文言の全面改修 / 実装全体の再設計

---

## Goal Statement

SoChi BLOCKS の空状態表示について、
`情報はあるが意味が通らない表示`
ではなく、
`まだ始めていないだけだと自然に分かる表示`
へ整理できるかを確認する。

今回の follow-up は、
進捗 UI 全体を作り直すことではなく、
未開始状態で
`壊れて見えない`
ことを最優先にする narrow run とする。

---

## Background

初回体験改善では、
ユーザーが
`何をすればよいか`
で止まらないことに加えて、
`今見えている表示は正常なのか`
で不安にならないことも重要である。

特に
`Cleared: 0 / 0`
のような表示は、
内部状態としては正しくても、
初見ユーザーには
`まだ始めていない`
より
`何か壊れている`
と読まれる可能性がある。

そのため今回は、
空状態を
`ゼロの報告`
ではなく
`最初の一歩を促す自然な状態`
として表現できるかを見る。

---

## Success Criteria

1. 主語が最後まで
   `空状態表示の改善`
   に留まっている
2. 空状態が
   `壊れて見える表示`
   から
   `未開始の自然な状態`
   へ読み替わる構成になっている
3. 初見ユーザーにとって
   `次に何をすればよいか`
   が 1 行で分かる
4. 文言改善が
   broad UI redesign
   へ広がっていない
5. result で
   `この変更は不安を減らしそうか`
   を narrow に評価できる形になっている

---

## Expected Outputs

- 空状態表示の改善方針
- 差し替え候補文言
- `壊れて見える` を避けるための判断基準
- scope 外へ広げないための boundary

---

## Non-Goals

- 実績 / 進捗システムの全面改修
- ゲーム全体 UI の再設計
- トップページや遊び方ページの再設計
- React 実装そのもの
- 数値ロジックの変更

---

## Constraints

- 空状態では
  `未開始`
  が自然に伝わることを優先する
- 数値を見せるより、
  状態の意味が伝わることを優先する
- 文言は短く、
  次の行動を邪魔しないこと
- `壊れて見えない`
  ことを最低条件に置く

---

## Notes For Planner

- 最重要判断は
  `空状態で何を表示しない方がよいか`
  である
- ゼロ値をそのまま見せることが有益か、
  それとも未開始メッセージへ置き換える方が自然かを判断する
- 文言だけでなく、
  CTA や導線とのつながりも軽く見る
- `初回体験の不安を減らす`
  以上の主語に広げないこと
