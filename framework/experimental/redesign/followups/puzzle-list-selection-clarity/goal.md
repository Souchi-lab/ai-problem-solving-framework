# Goal
---
## Objective

Make the puzzle list easier to choose from at a glance.

This follow-up should focus on the smallest UI/UX change that reduces hesitation when users are deciding which puzzle to open next.

## Scope

- puzzle list / puzzle card selection experience
- clarity of "which one should I choose?"
- local visual or copy adjustments that improve scanability

## Non-Goals

- full list redesign
- recommendation engine expansion
- difficulty system redesign
- persistence / personalization logic

## Success Criteria

1. The current selection hesitation is described precisely.
2. The main ambiguity source is identified.
3. The proposed fix stays local to the puzzle list surface.
4. It is clear whether the gain comes from copy, emphasis, grouping, or a small ordering cue.

## Expected Output

- a narrow `plan.md`
- if needed, a small `build.md`
- a `result.md` that records the exact clarification path chosen

## Notes For Planner

Start by checking:

- how puzzle cards are currently labeled
- whether a user can tell which card is the easiest next choice
- whether the hesitation comes from too little distinction, too much repetition, or weak grouping

The key question is not "how to redesign the whole list."
It is "what is the smallest change that makes choosing feel easier."
