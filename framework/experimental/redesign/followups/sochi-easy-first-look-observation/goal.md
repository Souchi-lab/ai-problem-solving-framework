## Goal Statement

SoChi BLOCKS の representative な easy 問題 1 件を選び、
既に定義済みの 4軸

- discoverability
- first move clarity
- early success expectation
- rules ambiguity pressure

に沿って、
初見向け easy としての first-look observation を具体的に記述する
small follow-up を定義する。

今回の主題は、
新しい評価枠を作ることではない。

主題は、
既存の observation frame を
実問題 1 件に着地させ、
`observation / interpretation / ambiguity`
を実データとして残すことである。

---

## Background

前段の `sochi-easy-first-look` 系では、
`easy label` と `first-time usability` を分け、
初見向け easy を見るための 4軸が定義された。

さらに `sochi-easy-first-look-evidence` 系では、
その 4軸を representative な easy 問題 1 件に当てる
evidence run の型が Accept で閉じられた。

したがって次に必要なのは、
抽象論を増やすことではなく、
実際の問題 1 件を対象にして、
4軸ごとの観察結果を埋めることである。

---

## Success Criteria

今回の goal は、
次の条件を満たす形で定義されていればよい。

1. 対象が representative な easy 問題 1 件に固定されている
2. 主題が
   `4軸による具体観察`
   に固定されている
3. 出力が
   `observation / interpretation / ambiguity`
   を各軸ごとに残せる形になっている
4. easy 群全体の一般化や taxonomy 議論へ広がっていない
5. redesign や改善案の設計へ進んでいない
6. 次の plan で、
   観察対象の固定方法と
   記録形式を narrow に定義できる

---

## Expected Outputs

この run で期待する出力は次のとおり。

- representative easy 問題 1 件の観察 run framing
- 4軸ごとの観察記録単位
- `observation / interpretation / ambiguity`
  の記録形式
- 今回扱うこと / 扱わないこと の明確化

---

## Non-Goals

今回の run でやらないことは次のとおり。

- easy 群全体の横断レビュー
- difficulty taxonomy の再議論
- puzzle rebalance の判断
- UI / tutorial / copy 改善案の設計
- 新しい評価軸の追加
- broad onboarding redesign

---

## Constraints

- scope は representative な easy 問題 1 件に限定する
- 使う軸は既存の 4軸に限定する
- 出力は observation-first であり、
  改善提案-first にしない
- synthesis は対象 1 件に留め、
  easy 群全体へ一般化しない
- small follow-up として扱い、
  broad redesign に進まない

---

## Notes For Planner

Planner は次を先に固定すること。

- 対象問題は 1 件で十分である
- この run は
  `問題の良し悪しを最終判定する run`
  ではなく
  `4軸の observation を実際に埋める run`
  である
- 各軸について
  `observation / interpretation / ambiguity`
  を分けて残せる形にする
- compare を使うとしても、
  confusion source の切り分け補助を超えないようにする
- 結果を easy 群全体へ一般化しないようにする
