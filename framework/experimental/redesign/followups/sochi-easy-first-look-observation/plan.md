## Observation Record Unit

今回の最小記録単位は、
各軸ごとに次の3つを残すことである。

1. **Observation**
   - 初見時に見える事実
   - どこで止まるか / どこで進めるか
   - 何が目に入り、何が progress feeling を生むか

2. **Interpretation**
   - その observation が
     初見向け easy として何を示すか

3. **Ambiguity / Open Question**
   - まだ断定しきれない点
   - evidence 不足の点
   - friction source が単独でない可能性

ambiguity は未解決事項ではなく、
この run で保留にしてよい観察結果として記録する。

ここでは、
Observation と Interpretation を混ぜないことが重要である。

- Observation は見えた事実
- Interpretation はその意味づけ

として分けて残す。

---

## Axis-by-Axis Observation Use

### 1. Discoverability

見ること:

- 初見でどこに注目すべきか拾えるか
- 盤面 / 空き / ピースの関係が見えるか
- 問題の入口が自然に立つか

残すこと:

- observation
- interpretation
- ambiguity

### 2. First Move Clarity

見ること:

- 初手候補が自然に立つか
- 最初の一手を置く場所の見当がつくか
- 候補過多または候補欠如で停止しないか

残すこと:

- observation
- interpretation
- ambiguity

### 3. Early Success Expectation

見ること:

- 初手後に進展感があるか
- 数手以内に
  `できそう`
  `分かったかも`
  が立つか
- 継続意欲を支える手応えがあるか

残すこと:

- observation
- interpretation
- ambiguity

### 4. Rules Ambiguity Pressure

見ること:

- 難しさではなく
  見方や前提ルールの曖昧さで止まっていないか
- confusion の主因が difficulty ではなく ambiguity にあるか
- `easy-looking but confusing`
  の兆候があるか

残すこと:

- observation
- interpretation
- ambiguity

## Execution Plan

### Step 1. Observation target を固定する

representative easy 問題 1 件を選び、
今回の観察対象として固定する。

### Step 2. First-look sequence を最小限で仮置きする

初見ユーザーがその問題に触れたとき、

- 最初に何が目に入るか
- どこから考え始めそうか
- どこで止まりそうか
- どこで progress feeling が出るか

を最小限で仮置きする。

first-look sequence は
4軸観察を助けるための最小補助線に留め、
独立した UX 設計記述にはしない。

### Step 3. 4軸ごとに観察を分解する

全体感想ではなく、
4軸ごとに observation / interpretation / ambiguity を分けて埋める。

### Step 4. Ambiguity を明示的に残す

断定しきれない点は無理に潰さない。

- evidence 不足
- friction source の複合性
- interpretation の保留

として残す。

### Step 5. Narrow synthesis で閉じる

最後は対象1件についてのみ、

- どこが entry-friendly か
- どこが friction か
- 何がまだ open か

をまとめる。

改善案設計や群全体の一般化には進まない。
