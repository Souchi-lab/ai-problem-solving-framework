# Goal

---

## Follow-up Context

- Parent series:
  SoChi BLOCKS 初回体験改善
- Previous result:
  初回導線は first playable moment を優先して評価すべきである
- New trigger:
  easy 問題が「簡単そうに見える」だけで、
  本当に初見向け easy として機能しているかは未確認である
- Scope limit:
  easy 問題の first-look suitability のみ
- Non-goals:
  full difficulty rebalance / 全問題の再分類 / implementation

---

## Goal Statement

SoChi BLOCKS の easy 問題が、
本当に初見ユーザー向けの easy として機能しているかを扱う
small follow-up を定義する。

今回の主題は、
「easy とラベルされているか」ではなく、
「初見ユーザーにとって entry-friendly な最初の問題として成立しているか」
である。

---

## Background

これまでの follow-up では、
SoChi BLOCKS の初回導線を
first playable moment の観点から扱ってきた。

その流れでは、
最初の1問に入れるかどうかだけでなく、
最初に触れる問題自体が
初見向けとして妥当かどうかも重要になる。

easy 問題が名目上 easy でも、

- 初見で何をすればよいか分からない
- 説明なしでは最初の一手が出ない
- easy というより rules ambiguity が強い

のであれば、
初回体験上の easy としては再評価が必要になる。

---

## Success Criteria

今回の goal は、次の問いを narrow に扱える形になっていればよい。

1. 主題が
   「easy 問題は初見向け easy として機能しているか」
   に固定されている
2. difficulty 全般ではなく、
   first-look suitability に焦点が当たっている
3. `easy label` と `first-time usability`
   を分けて扱える
4. 後続 plan で、
   `discoverability / first move clarity / early success expectation`
   のような観点へ分解できる
5. broad puzzle rebalance や
   full onboarding redesign に広がらない
6. small follow-up として
   SoChi BLOCKS 初回体験改善系列に接続できる

---

## Expected Outputs

この run で期待する出力は次のとおり。

- easy 問題の first-look suitability という問いの framing
- `easy label` と `初見向け easy` の区別
- 後続 plan に渡せる最小観点
- 今回扱うこと / 扱わないこと の明確化

---

## Non-Goals

今回の run でやらないことは次のとおり。

- SoChi BLOCKS 全問題の difficulty 再評価
- puzzle difficulty balancing 全般
- easy / normal / hard の再命名
- full onboarding redesign
- 実装変更や puzzle 差し替え判断

---

## Constraints

- scope は easy 問題の first-look suitability に限定する
- `easy` を difficulty taxonomy として論じすぎない
- 主題は
  「初見で最初の問題として成立するか」
  であり、
  後半の mastery ではない
- small follow-up として扱い、
  新しい大型系列にしない

---

## Notes For Planner

Planner は次を先に固定すること。

- easy というラベルの妥当性と、
  初見 entry 用としての妥当性は同じではない
- 最初に見るべきは、
  問題自体の難易度一般ではなく
  初見ユーザーの first look である
- もし compare を使うなら、
  `easy-looking but confusing`
  と
  `actually entry-friendly`
  の差を切る時だけに留める
- broad rebalance や puzzle taxonomy の再設計へ話を広げない
