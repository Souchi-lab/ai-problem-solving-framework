# Goal
---
## Objective

Clarify what the top-page progress area means so users can understand it at a glance.

This follow-up should focus on the smallest change that makes the progress summary feel immediately understandable and relevant.

## Scope

- top-page progress summary area
- labels, short explanation, and small meaning cues
- user understanding of what the numbers/chips represent

## Non-Goals

- progress system redesign
- account / sync / cloud progress features
- leaderboard or achievement expansion
- full homepage redesign

## Success Criteria

1. The current ambiguity around the progress summary is described precisely.
2. It is clear whether the issue is label, meaning, empty-state handling, or local context.
3. The proposed fix stays local to the progress surface.
4. It is clear whether the gain comes from copy, emphasis, or no change.

## Expected Output

- a narrow `plan.md`
- if needed, a small `build.md`
- a `result.md` that records the exact clarity path chosen

## Notes For Planner

Start by checking:

- whether users can tell what the progress numbers count
- whether it is obvious that this is local progress
- whether the empty / zero-clear state is understandable

The key question is not "how to redesign progress."
It is "what is the smallest change that makes the current progress area self-explanatory."
