## 2. タグ改善案

### 表記統一

`#SoChiBlocks` に統一する（現在の自動投稿スクリプト・caption ファイルの主流に合わせる）。

### タグ分類の再定義

| 種別 | タグ | 用途 |
|---|---|---|
| 固定タグ | #SoChiBlocks | ブランド認知・常時 |
| 固定タグ | #ブロックパズル | ジャンル認知・常時 |
| カテゴリタグ | #論理パズル | 内容分類・投稿種別によって使う |
| 到達タグ | #脳トレ | 広域リーチ・Easy/Medium 向け |
| 到達タグ | #パズル | 広域リーチ・汎用 |
| 難度訴求タグ | #難問 | Hard/Hardest 向け限定 |

### 投稿タイプ別組み合わせルール（改善案）

| 難易度 | 推奨タグ構成 |
|---|---|
| Easy / Medium | #SoChiBlocks #ブロックパズル #論理パズル #脳トレ |
| Hard / Hardest | #SoChiBlocks #ブロックパズル #論理パズル #難問 |

変更点:

- #論理パズル をカテゴリタグとして全難易度に追加
- Easy/Medium の #脳トレ・Hard/Hardest の #難問 は位置づけを「到達 / 難度訴求」として明示

### 効果の予測（実運用前）

- #論理パズル 追加により、パズル系検索流入が増える可能性がある
- タグ種別の明示により、投稿ごとのタグ選択が一貫しやすくなる
- 表記統一により、#SoChiBlocks での集約検索が機能する

※ これは予測であり、効果の確認は実運用後に行う。

### 実運用後の確認観点

- #論理パズル によるインプレッション変化（比較期間: 2週間目安）
- #SoChiBlocks 統一後の検索・タグクリックの動向
- タグ構成の運用しやすさ（迷わず使えるか）

## 3. 形式評価（4観点）

現行 4 点セット（goal / plan / review / result）を軽量タスクに適用した評価。

### 作業量

評価: **ちょうどよい**

各フェーズで手を動かす量は、タスクの軽さに対して過剰ではなかった。
goal と plan の記述はやや丁寧だったが、二層目的（形式検証込み）がある分は妥当。
純粋なタグ改善のみなら、goal + plan で少し圧縮できる余地はある。

### 判断量

評価: **ちょうどよい**

plan でタグ3種の定義・組み合わせルールを決める判断は、
軽量タスクとしての難度に収まっていた。
review のゲート3点も機械的に確認できる程度だった。

### 文書量

評価: **やや重い**

goal と plan の文書量は、題材（タグ改善）の規模より一回り大きい。
ただしこれは二層目的（形式検証）を含んでいたため、今回は許容範囲内。
純粋な軽量タスク（形式検証なし）なら、各ファイルを半分以下に絞れる。

### 効果の見えやすさ

評価: **ちょうどよい**

タグ改善案は具体的な構成として result に出せた。
効果の予測と実運用後の確認を分けて書けており、判断の曖昧さは残っていない。

---

## 4. 軽量 variant 検討への示唆

今回の評価から見えてきたこと:

- 4点セットは「二層目的あり」や「形式検証あり」のタスクには適合する
- 純粋な軽量タスク（変更が小さく、効果が自明に近い）では **文書量が一回り過剰**
- 最も削減しやすいのは goal と plan の各セクション数

軽量 variant の候補として、次が自然に出てくる:

| 候補 | 構成 |
|---|---|
| 2点セット | goal + result のみ |
| 圧縮4点セット | 各ファイルのセクションを半分以下に絞る |
| checklist 型 | plan を箇条書き1枚に置き換える |

次に軽量 variant を試すなら、**2点セット（goal + result）** から始めるのが最小。
