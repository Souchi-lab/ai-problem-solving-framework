## ✅ 解決済み (Resolved)

*   **[P0] 狭い画面でのレイアウト崩壊**:
    *   `lg:flex-row` 導入により、狭い画面では縦に並ぶレスポンシブな挙動を確保。
*   **[P0] スクロール時のコンテキスト喪失**:
    *   ラン名、フェーズバッジ、Primary Command、Artifacts ヘッダーを `sticky` 化。常に何をしているかが見える「司令官の視点」を確保。
*   **[P1] Readiness Note の埋没**:
    *   琥珀色（Amber）の枠線と背景、および `sticky` 配置により、実行前の警告を見落とさない設計に改善。
*   **[P2] 子ラン詳細時の「隣の芝生」問題**:
    *   「Sibling Runs」セクションと、ヘッダー内のターゲット切り替えスイッチにより、親子・兄弟間の移動が飛躍的にスムーズ化。
*   **[P2] Primary Command の存在感**:
    *   単なるテキストから、コピー機能付きの専用パネルとしてヘッダー内に「特等席」を用意。

## ⚠️ 継続検討中 (Remaining Polish)

### 1. 実行ボタンと保存フィードバックの強化
- **現状**: Rework コメント保存後のフィードバックがテキストのみで、次のアクション（再実行）への導線が静的。
- **改善案**: 保存成功時にボタンの色を変化させる、または「保存済み」状態であることを視覚的（チェックアイコン等）に強調し、安心して次の `Execute` を押せるようにする。

### 2. サイドバーの情報密度と視認性
- **現状**: 長いラン名が `break-words` で複数行になり、リストが縦に長くなっている。また、多数の小バッジが密集してノイズになっている。
- **改善案**: ラン名を一行に制限 (`truncate`) し、ホバーで全名を表示。バッジを整理（主要な Phase/Priority 以外は整理またはアイコン化）して余白を確保する。

### 3. ナビゲーションラベルの洗練
- **現状**: 「Target」ボタンや「Target」というラベルが、純粋な「詳細を開く」というナビゲーションを指すのか、状態を変更するのかが初見で分かりにくい。
- **改善案**: 「Open Detail」「View Child」など、より直感的なアクションワードへ変更する。

### 4. サイドバーの幅の自由度
- **現状**: `w-72` 固定。
- **改善案**: ドラッグによる幅調整、または最小化（アイコンのみ）モードを導入し、メインコンテンツ（Artifact プレビュー）の領域をさらに拡張可能にする。

## 💎 次のフェーズの挑戦 (Future Exploration)

*   **「成果物の文脈記憶」**: 親・子ランを切り替えても、前回見ていたファイル（例：`goal.md`）を選択したままにする機能。
*   **「実行中のライブログ」**: 実行ボタンが `Running...` になっている間、何が起きているかの詳細な進捗をさりげなく表示し、司令官の「退屈と不安」を解消する。
