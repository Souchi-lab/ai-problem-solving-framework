# Viewer Improvement Discovery Report 🚀

総合テストの結果、Codex 先生も驚くかもしれない（？）「改善の種」を 8 つ収穫しました！
実際に動かしてみると、意外なところに「おや？」というポイントが隠れていましたね。

## 1. 検出ロジックの「沈黙の 4 行」ルール 🤫
- **現状**: `PhaseDetector` が「3 行以下のファイルは内容なし」とみなして `SETUP_NEEDED` に戻してしまいます。
- **摩擦**: 短く完璧な Goal を書いても「もっと書け！」と言われているようで、初心者が迷う原因になりそうです。

## 2. 画面サイズの「柔軟性」問題 📱
- **現状**: 3 列固定レイアウトのため、解像度が低いとかなり窮屈です。
- **摩擦**: カラムの折り畳みや、プレビューパネルの最大化ボタンがあると、もっと「没入感」が出そうです。

## 3. 子ラン詳細時の「隣の芝生」が見えない問題 👁️
- **現状**: 子ランを Target にすると、他の同僚（他の子ラン）がリストから消えてしまいます。
- **摩擦**: 001c1 と 001c2 を素早く見比べたいとき、いちいち Parent タブに戻る手間があります。
- **解決案**: ユーザーさんにより「Sibling Runs」セクションが実装され、大幅に改善されました！

## 4. スクロール耐久レース 🏃‍♂️
- **現状**: 詳細パネルが縦に長く、アクションボタンまでスクロールが必要です。
- **摩擦**: メインアクションは常に画面下部にフローティングさせるか、上部にも配置すると操作性が向上します。

## 5. 「プライマリコマンド」のただのテキスト化 ⌨️
- **現状**: コマンドが表示されていますが、クリックしても何も起きません。
- **摩擦**: ここがそのまま「実行ボタン」になっていれば、視線の移動を最小限に抑えられます。

## 6. 保存ボタンの「変化」が控えめ 💾
- **現状**: Rework コメントを保存しても文字が出るだけで見逃しやすい。
- **摩擦**: 保存後はボタンの色を変えるか、アニメーションを入れると達成感が出ます。

## 7. ステートの同期ズレ（稀に発生） 🔄
- **現状**: ターゲットを切り替えてもタブ名が古いままになる現象を観測。
- **解決案**: ユーザーさんにより `Promise.all` を用いた原子的な状態更新が実装され、解消されました！

## 8. サイドバーの「柔軟性」欠如 🌲
- **現状**: ツリーの横幅が固定されており、長いラン名が途切れます。
- **摩擦**: 幅をドラッグで調整したい、あるいは長い名前でも 1 行に収めたいというニーズがあります。

---
## 💎 本質的な UX（ユーザー体験）のチェックポイント

1. **「文脈の維持（Context Retention）」**: 親子切り替え時も選択アーティファクトを記憶する。
2. **「安心感とフィードバック（System Feedback）」**: 実行中の進行ディテールを可視化する。
3. **「リカバリのスムーズさ（Error Recovery）」**: 失敗時にエラー箇所へ自動案内する。
4. **「完了の喜び（Delight）」**: `COMPLETE` 到達時に特別な演出をする。
